# Benchmarks — don't take our word for it

Rerun everything on your own machine:

```bash
cargo run --example bench
```

No network, no model key: the eval set is generated by seeded RNGs, token
counts use the same estimator the library ships, and statistics are
dependency-free textbook implementations (verified against known values in
`tests/bench_stats.rs`).

## What it measures — and what it doesn't

50 synthetic long conversations. Each one:

1. opens with an **early-turn fact** — a user constraint stated once
   (`msg_001`, e.g. *"my budget is under $500"*),
2. buries it under filler chatter (small talk + medium-specificity turns),
3. ends with a **final question** answerable only if the fact survived
   compaction (*"what was the key thing I asked you to remember"*).

Correctness = **retention**: does the compacted history still contain the
answer keyword? Retention is the necessary precondition for a correct final
answer, and it is the part CTX controls — the model can't use what isn't
there. **No model runs in this eval.** Any table quoting these numbers must
say "retained", never "answered". (Plugging `kept_history` into a real model
and grading answers is the obvious next step; retention bounds that score
from above.)

Scope, stated plainly: this eval tests the **separable-importance regime** —
needles written to be detectable, filler screened to be ignorable (see
"Methods" below). It shows that *when importance is separable from recency,
merit retention beats recency retention*. It does not measure Themis's
precision on wild text, and the scorer-separation line the runner prints must
never be quoted as one.

## Methods (how the eval resists its own bias)

- **Stratified lengths, enforced by construction.** Shorts must fit the
  canonical 350-token budget; longs/adversarials must exceed it by 50+
  tokens. The harness adjusts filler counts until the regime holds, on every
  seed — bucket membership is eval design, never influenced by any
  strategy's behavior. (For the canonical seed the enforcement loops are
  no-ops; the numbers below are untouched by them.)
- **Leak audit.** The harness panics if any input keyword appears outside
  turn 1, or if a needle is vacuous (absent even from turn 1). Future filler
  edits can't silently inflate scores.
- **Probe excluded from grading.** The final question is the test instrument,
  not evidence; grading skips it by message id.
- **No position signal in Moirai** (verifiable in `src/moirai.rs`), so the
  needle sitting at turn 1 flatters no one — scores drive everything.
- **Uncertainty reported, not rounded away.** Wilson 95% intervals on every
  rate; paired McNemar tests (continuity-corrected) instead of chi-square,
  since all strategies face the same conversations.
- **Budget sweep.** The canonical 350 could be a cherry-pick; the runner
  re-measures at 80/150/350/600/1000 so you can see the gap live in its
  regime and vanish outside it.
- **Multi-seed stability.** Same eval at 5 seeds; reported as mean [min, max].

## Eval set composition

| Kind | Count | Total tokens vs. 350-token budget | Expected outcome |
|---|---|---|---|
| `short` | 31 | ~100–145, fits entirely | all tie at 100% (31/31, null result) |
| `long` | 16 | ~430–535, forces cuts | Lethe drops the fact (oldest first); merit keeps it |
| `adversarial` | 3 | ~500, fact embedded in one ~180-token journal dump | window and packing fail; sentence compression recovers it |

## Representative run (`cargo run --example bench`)

Headline = canonical seed (1701), canonical budget (350):

| Strategy | Retained | Wilson 95% | Avg tokens | Med latency |
|---|---|---|---|---|
| Lethe — forgets oldest first, no judgment | 62.0% (31/50) | [48.2%, 74.1%] | 207.5 | 0.04 ms |
| Moirai — decides what survives on merit | 94.0% (47/50) | [83.8%, 97.9%] | 207.3 | ~2 ms |
| Mnemosyne — compresses old turns, keeps recent verbatim | 100.0% (50/50) | [92.9%, 100%] | 200.2 | ~14 ms |

Same conversations. Same token budget. The only difference is what got kept.

Paired significance (McNemar, same 50 conversations):

```text
McNemar lethe vs moirai:     discordant 16/0, chi2=14.06, p<0.0001  (significant)
McNemar moirai vs mnemosyne: discordant 3/0,  chi2=1.33,  p=0.2482  (NOT significant)
```

Read that second line carefully: at n=50, the 94→100 gap is suggestive, not
proven. The honest headline is "Moirai beats Lethe decisively; Mnemosyne's
edge over Moirai needs a bigger eval to call." The intervals say the same
thing — [83.8, 97.9] overlaps [92.9, 100].

Retention by bucket (canonical seed):

| Bucket | n | Lethe | Moirai | Mnemosyne |
|---|---|---|---|---|
| short | 31 | 100% | 100% | 100% |
| long | 16 | 0% | 100% | 100% |
| adversarial | 3 | 0% | 0% | 100% |

Bucket cells are small-n location markers, not standalone claims — adversarial
3/3 is Wilson [44%, 100%]. Read this table for *where* wins happen; read the
headline intervals for *how surely*.

Stability across seeds (budget 350): all three strategies reproduce exactly
at all 5 seeds. That flatness is structural, not suspicious — stratified
regimes plus wide scoring margins make outcomes seed-independent by design.

Budget sweep (canonical seed) — the anti-cherry-picking exhibit:

| Budget | Lethe | Moirai | Mnemosyne |
|---|---|---|---|
| 80 | 0% | 94% | 0% |
| 150 | 62% | 94% | 100% |
| 350 | 62% | 94% | 100% |
| 600 | 100% | 100% | 100% |
| 1000 | 100% | 100% | 100% |

The merit gap lives in the middle regime and vanishes where everything fits
(top) — and compression collapses where nothing fits (bottom: Mnemosyne 0%
at 80, saying so on its receipts). If the canonical 350 had been picked to
flatter anyone, the sweep would show it. It shows the opposite: the ranking
is regime-dependent, and the regimes are all on the table.

Two footnotes. First, token usage is nearly identical across strategies —
merit packing doesn't spend *fewer* tokens, it spends the *same* budget on
better messages. Second, latencies are debug-build, same-machine medians
(1 warmup + 10 timed passes): Lethe is a memcpy, Moirai pays for scoring
every message, Mnemosyne pays for extractive ranking. Rerun with `--release`
for quotable latencies; a model-call summarizer or model-based scorer would
dominate latency instead — measure yours.

Validity line (what the runner's scorer check actually is):

```text
validity: leak audit PASS (keyword unique to turn 1 in all 50 inputs); probe excluded from grading
themis separation (screened pool): needles 50/50 >= 0.50, filler 0/675 >= 0.50
```

The second number exists to check the eval *can discriminate* (needles
detectable, filler ignorable) — the filler pool was screened for hint
substrings when written, so quoting 0/675 as "Themis precision" would be
circular. Don't.

## Per-conversation detail

The runner prints one line per conversation (`convo_01 … convo_50`) with total
input tokens and each strategy's verdict, so you can inspect exactly where
any strategy wins or loses. Change the seeds, the budgets, the filler pools,
or the fact set in `examples/bench.rs` and rerun — every strategy implements
`Compactor`, so new contenders slot into the same table. Break the eval's
assumptions (e.g. a filler containing a keyword) and the leak audit fails
loudly instead of letting the numbers drift.

## What's still honest future work

- **Real-model grading.** Retention bounds answer correctness from above; the
  remaining step is feeding `kept_history` to a model and grading answers.
  The harness mode exists and the first keyed run landed 2026-09-06
  (gemini-3.5-flash-lite, n=50 — see "Real-Model Answer Eval" below); still
  open is repeating it across models and runs (3+ runs per conversation,
  mean ± std dev).
- **Cost per correct answer.** Tokens-per-retained-needle divides out of the
  table (avg tokens ÷ retention) — multiply by your provider's price.
- **Bigger n for the Moirai/Mnemosyne gap.** p=0.25 at n=50: rerun the same
  harness with more conversations (or harder needles) to call it.
- **Wild-type filler.** An unscreened filler pool would measure Themis
  precision for real — currently unmeasured by design.
- **Real conversations.** Synthetic evals support the mechanism in the tested
  regime; the next step
  is the same retention check against anonymized real transcripts, which have
  messier structure (interruptions, corrections, multiple needles at once).

## Real-Model Answer Eval (n=50, gemini-3.5-flash-lite — measured 2026-09-06)

> **No material contradiction with the retention eval.** Same ranking
> (Lethe < Moirai ≤ Mnemosyne), same significant gap (McNemar p=0.0003 on
> L2 answers). Two honest attenuations: Mnemosyne's perfect 100% retention
> becomes 96% answers (summaries preserve text the model sometimes can't
> use), and everything below was produced by a lite-class free-tier model —
> read it as "with Flash-class answers", not as a universal constant.

### Why a second eval

The text-retention eval proves CTX keeps the right *text*. It does not prove
keeping it produces a better *answer* — a model can fumble a retained fact or
guess right without it. This mode sends each conversation's compacted history
(all three strategies, same 50 conversations) to a real backend for the final
turn and grades what comes back.

### How to run it

```bash
cargo run --example bench -- --with-model [--model-limit N] [--model-pause-ms MS]
```

| Env var | Default | Meaning |
|---|---|---|
| `CTX_MODEL_API_KEY` (or `GROQ_API_KEY`, `OPENAI_API_KEY`) | — | **Required.** Never printed, logged, or persisted (custom `Debug` redacts it; the answers file is scanned for leaks in review). |
| `CTX_MODEL_BASE_URL` | `https://api.groq.com/openai/v1` | Any OpenAI-compatible `/chat/completions` endpoint. Reached via `curl`, request bodies via temp files (no shell quoting hazards). |
| `CTX_MODEL_NAME` | `llama-3.3-70b-versatile` | Recorded in every report and answers file. |
| `CTX_PRICE_IN_PER_M` / `CTX_PRICE_OUT_PER_M` | `0.59` / `0.79` USD | Price basis for cost math (Groq list circa 2026 — override for your provider). |
| `CTX_MODEL_PAUSE_MS` / `--model-pause-ms` | `1000` | Spacing between calls (rate-limit courtesy). |

Fixed per run and recorded: system prompt
("Answer the user's final question using only the conversation history above.
Reply in one or two sentences."), temperature 0, max tokens 256. No key →
loud refusal, exit 2, no silent fallback. Any failed call → recorded loudly,
exit 1 at the end, so partial results can't pass as complete.

Cost estimate for the full 50×3 run: ~150 calls × ~550 tokens ≈ 82K tokens,
roughly **$0.02–0.06** at current mini/70B-class pricing. Every answer is
persisted with full run metadata to `benchmarks/model_answers.json`
(regenerated per run; rows carry grades, token usage, latency, and errors).

Free dry run (no key, deterministic, exercises all plumbing):

```bash
python benchmarks/mock_model_server.py 18080
$env:CTX_MODEL_API_KEY = "dry-run"
$env:CTX_MODEL_BASE_URL = "http://127.0.0.1:18080"
$env:CTX_MODEL_NAME = "mock-perfect"
cargo run --example bench -- --with-model --model-limit 6 --model-pause-ms 0
```

### Graders

| Grader | Rule | Role |
|---|---|---|
| L1 | keyword substring, case-insensitive (the retention probe, applied to answers) | strict baseline, continuous with the text eval |
| L2 | rubric essentials, all token-matched (folded, plural-tolerant: "peanuts"→"peanut", but "5000"≠"500", "open"≠"pen") | paraphrase-tolerant headline |

Published rubric (in `examples/bench.rs`, reviewable):

| Needle | Essentials |
|---|---|
| budget under $500 | `500`, `budget` |
| allergic to peanuts | `peanut` |
| Amara, deadline Friday | `amara`, `friday` |
| travel by train | `train` |
| epi pen | `epi`, `pen` |
| journal ($500) | `500`, `budget` |

L2 tolerates rephrasing but requires digits-as-digits ("five hundred" fails
"500") — the documented gap. **LLM-as-judge is future work, deliberately
not implemented:** grading model answers with another model call is circular
until the judge itself is validated (agreement-vs-human study, bias checks),
and an unvalidated judge would launder opinions into numbers. When it lands,
it must be reported *alongside* L1/L2, never instead of them.

### What gets reported (and the divergence taxonomy)

Per strategy: answer accuracy under L1 and L2, L1–L2 agreement, cost/call,
median latency *including* the model call, and McNemar on L2 answers. Then
retention-vs-answer on the same conversations, per strategy:

| Cell | Meaning |
|---|---|
| both-right | pipeline worked end to end |
| **retained-but-wrong** | compaction succeeded, generation failed — bounds the model's contribution |
| **dropped-but-right** | inference from remaining context, or luck — bounds the eval's looseness |
| both-wrong | the expected failure |

Both off-diagonal cells are listed by conversation id in the report. Per the
standing rule: **if model results contradict the retention conclusions in any
material way, that contradiction leads this section** — it is the finding, not
an embarrassment to bury.

### Results (first complete run — verbatim)

Run history, disclosed: the first attempt targeted `gemini-2.5-flash` and
failed whole (Google retired the ID for new users); the second attempt on
`gemini-3.6-flash` died at 22/150 calls against a 20-request/day free-tier
cap — partial, discarded, reported here so the model choice reads as quota
survival, not cherry-picking. What follows is the first *complete* run:
n=50, all three strategies, 150/150 calls, 0 errors.

```text
==== Real-model answer eval (n=50, openai-compat base=https://generativelanguage.googleapis.com/v1beta/openai model=gemini-3.5-flash-lite temp=0 max_tokens=256) ====
system prompt: "Answer the user's final question using only the conversation history above. Reply in one or two sentences." (temperature 0, max_tokens 256)
graders: L1 = keyword substring (strict baseline), L2 = rubric essentials (paraphrase-tolerant)

strategy         n      L1      L2   agree cost/call       medMs tokIn+Out
lethe           50   62.0%   62.0%  100.0%   0.0000$      1102.1      9318
moirai          50   90.0%   92.0%   98.0%   0.0000$      1097.1      9457
mnemosyne       50   94.0%   96.0%   98.0%   0.0000$      1134.1     12155
McNemar (L2 answers) lethe vs moirai: discordant 15/0, chi2=13.07, p=0.0003

retention (text) vs answer (L2) — same conversations:
strategy    bothRight retainedButWrong  droppedButRight  bothWrong
lethe              31                0                0         19
moirai             46                1                0          3
mnemosyne          48                2                0          0
retained-but-wrong (moirai; compaction ok, generation failed): convo_33
retained-but-wrong (mnemosyne; compaction ok, generation failed): convo_35, convo_47

saved benchmarks/model_answers.json (150 rows, 0 errors)
model spend total: $0.0000 (150 rows; usage reported by API)
```

Reading it:

- **Same verdict, smaller numbers.** Retention said 62/94/100; answers say
  62/92/96 (L2). The ranking survives the model, the Lethe–Moirai gap stays
  significant (p=0.0003), and Lethe shows zero divergence in either direction:
  with this model, lost text is never recovered and kept verbatim text is
  always used (31/31).
- **The off-diagonal cells are the findings.** Moirai's convo_33 kept the
  Amara/Friday fact but answered only "Your deadline is Friday" — incomplete,
  correctly failed. Mnemosyne's convo_35 and convo_47 kept the keyword inside
  summaries yet the model answered from surrounding compressed filler instead
  — a genuine compression artifact: *summarized text is preserved but less
  usable*. Dropped-but-right is 0 everywhere: nothing was inferred or lucky.
- **L1/L2 agree ~98–100%** at temperature 0 — the model echoes keywords
  rather than paraphrasing, so the paraphrase-tolerant grader changed almost
  nothing here. The L2 machinery stays for stronger or chattier models.
- **Cost/latency are free-tier artifacts, not findings.** Prices were zeroed
  (`$0.0000` by construction, not by measurement); ~1.1s median latency is
  one lite model behind one compat shim. Rerun with your provider's prices
  for quotable cost-per-answer.
